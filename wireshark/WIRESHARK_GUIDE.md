# Wireshark Capture & Analysis Guide

## Overview
This guide provides a reproducible workflow for capturing and analysing MQTT traffic generated by the **Industrial Machine Monitoring Network** project.  It focuses on the broker interactions for the three QoS levels (0, 1, 2) and on the impact of simulated network impairments.

---

## 1. Prerequisites
- Wireshark (or `tshark` for CLI) installed on the **E** machine (Arch Linux).  Install with:
  ```bash
  sudo pacman -S wireshark-cli
  ```
- Permissions to capture on the network interface (run as root or add your user to the `wireshark` group).
- The MQTT broker must be running and reachable (`10.219.34.191:1883`).
- The machine simulator must be active (run `python -m machine_simulator.machine_simulator`).

---

## 2. Capture Procedure
1. **Identify the interface** used for broker communication:
   ```bash
   ip route get 10.219.34.191
   # look for the "dev" field, e.g. eth0
   ```
2. **Start a capture** limited to MQTT traffic (TCP port 1883) and write to a file in `wireshark/captures/`:
   ```bash
   sudo tshark -i <iface> -f "tcp port 1883" -w wireshark/captures/qos1_normal.pcapng
   ```
   Replace `<iface>` with the interface name.
3. **Run the experiment** you want to capture (e.g. QoS 1 with normal network, or with latency).
4. **Stop the capture** with `Ctrl‑C`.  The file will be saved automatically.

---

## 3. Useful Wireshark Display Filters
| Purpose | Filter | Explanation |
|---|---|---|
| Show only MQTT packets | `mqtt` | Basic protocol filter. |
| CONNECT packet | `mqtt.msgtype == 1` | Client initiates connection. |
| CONNACK packet | `mqtt.msgtype == 2` | Broker response. |
| PUBLISH (any QoS) | `mqtt.msgtype == 3` | Telemetry and status messages. |
| PUBACK (QoS 1) | `mqtt.msgtype == 4` | Acknowledgement of QoS 1 publish. |
| PUBREC (QoS 2 step 1) | `mqtt.msgtype == 5` | Received request for QoS 2. |
| PUBREL (QoS 2 step 2) | `mqtt.msgtype == 6` | Release packet for QoS 2. |
| PUBCOMP (QoS 2 step 3) | `mqtt.msgtype == 7` | Completion of QoS 2 hand‑shake. |
| MQTT retain flag set | `mqtt.retain == 1` | Useful for LWT/offline status. |
| TCP retransmission | `tcp.analysis.retransmission` | Shows network‑level loss/retries. |
| TCP out‑of‑order | `tcp.analysis.out_of_order` | May indicate jitter. |
| Packet timestamps | `frame.time_relative` | Use for latency calculations. |

---

## 4. Extracting Metrics with `tshark`
You can extract timestamps and QoS information directly from the capture file:
```bash
# Example: list all PUBLISH packets with timestamps and QoS
tshark -r wireshark/captures/qos1_normal.pcapng -Y "mqtt.msgtype == 3" \
  -T fields -e frame.time_relative -e mqtt.qos -e mqtt.topic -e mqtt.msg
```
The output can be imported into a spreadsheet or analysed with Python (`pyshark`).

---

## 5. Analysing the Impact of Network Impairments
1. **Apply impairment** using `network/network_setup.sh` (e.g. `sudo ./network/network_setup.sh -d 150 -j 20 -l 5`).
2. **Capture** as described in section 2 while the simulator runs.
3. **Observe**:
   - Increased number of `tcp.analysis.retransmission` entries for higher loss.
   - Longer gaps between `PUBLISH` and its corresponding ACK/REC/REL/COMP packets (higher latency).
   - Duplicate `PUBLISH` packets when QoS 1/2 are retransmitted.
4. **Reset** the network after the experiment:
   ```bash
   sudo ./network/network_reset.sh
   ```

---

## 6. Documenting Results
Create a markdown file alongside the capture, e.g. `wireshark/captures/qos1_latency_150ms.md`, containing:
- Description of the experiment (QoS level, impairment settings).
- Summary table of key observations (packet loss, retransmissions, average RTT).
- Screenshots of Wireshark filtered views (use `Export Packet Dissections`).

## 7. Reference Captures (provided in the repository)
